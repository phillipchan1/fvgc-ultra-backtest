# 15m FVG Breakout Continuation — Reproduction Failure

**Date:** 2026-04-29
**Outcome:** Play rejected. Notion claims do not reproduce.

## Question

The Notion play "15m FVG Breakout Continuation" claimed:
- n=40, 93.3% WR @ 1R
- 70% hit 1R, 60% hit 2R, 55% hit 3R
- Median MFE 8.7R, PF 5.50

Mechanic: sweep of 15m FVG (non-reclaiming break) → opposing FVG inversion within 10 bars → first FVGC signal in **same direction as the break** within 40 bars.

The Notion page's "Trade List" property linked to `studies/reversal_fvg_continuation/results/trades_reversal.csv` — but inspection shows that file contains REVERSAL-direction trades only (124 in the filtered htf15m subset). The 40-trade continuation cohort isn't in the saved data.

We re-ran the analysis with continuation-direction logic to materialize the canonical list.

## Method

Forked `studies/reversal_fvg_continuation/run.py` to `studies/breakout_continuation/run.py` with one change at line 344:

```python
# Reversal (original):
entry_dir = 'short' if sweep['sweep_direction'] == 'up' else 'long'

# Continuation (this study):
entry_dir = 'long' if sweep['sweep_direction'] == 'up' else 'short'
```

All other logic preserved: same sweep detection, same opposing-FVG inversion scan, same simulate_trades engine, same entry-time filter (9:30–10:15 NY).

Slimmed grid to canonical config: 30s timeframe, reversal_window=10, entry_window=40. All 4 combinations of (sweep_reclaims, fvg_locality) were run.

## Sanity check — script is sound

Running with the original (unflipped) entry_dir reproduces the original 124-trade reversal cohort exactly. The underlying machinery works. Only the direction logic differs.

## Likely causes of the discrepancy

The Notion page itself notes: *"Discovered accidentally while building the reversal study — continuations through 15m FVGs were mixed into the reversal cohort and turned out to be the strongest subset."* This sounds like post-hoc filtering on a small sample.

Other possibilities:
- The original 40-trade list was generated by a code path not preserved in the saved repo
- Some hidden filter (e.g., entry must be PAST the broken FVG, tighter time gap from inversion to entry) was used in the original analysis but not documented in run.py
- Selection bias / hand curation

Without access to the original analysis script that produced the n=40 cohort, we cannot reconcile the numbers.

## Recommendation

**Reject the play.** All 4 grid configurations show 25–38% WR, dramatically below baseline. The mechanic does not have edge as currently defined.

Possible salvage paths (untested):
1. Require entry to be PAST the broken FVG (currently any FVGC after inversion is taken)
2. Tighter time gap from inversion to entry (≤2 bars instead of 40)
3. Multi-bar break confirmation
4. Filter to specific FVG sizes / freshness
5. Alignment with overall trend / pre-market direction

**Until something does reproduce, treat as rejected.**
